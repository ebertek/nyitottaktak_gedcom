# Contributor / agent notes

- Keep the Python CLI dependency-free and compatible with Python 3.10+.
- The upstream project is `ebertek/nyitottaktak_gedcom`. Propose changes in a branch/PR, not by editing deployed copies or committing user GEDCOM files.
- **Never commit real GEDCOM trees, archival search results, local caches, family documents, live-person information, or copied browser cookies.** Test identities must be fictional.
- Upstream search form constraints (from its public `search.js`): `nev` length 2–25 (may include periods); `szul_hely` and `anyja_neve` 2–25 (no periods); birth years 1850–1990; some document types support fewer filters; `too_many` means the result set is not exhaustive.
- Search names as Hungarian surname + given name; prefer the recorded birth name, preserve explicit aliases, and never invent maiden/married names. Use structured GEDCOM `GIVN`/`SURN` as fallback. Keep original birthplace but strip district suffixes for API filtering and place comparisons.
- Results are **identity leads only** and must not imply an individual was a collaborator. Keep negative/ambiguous identity evidence visible.
- Default to preview-only and conservative, sequential HTTP requests. Honor 403/429, cache responses, and never attempt access-control bypass.
- All CI tests must be offline, with synthetic records and mocked network access. Run `python -m unittest discover -s tests -v` and `python -m py_compile nyitottaktak_gedcom.py` for any code changes.
- Nyitott Akták's FAQ distinguishes a 6-os card (including unsuccessful/fictitious recruitment), 1956–1962 B-napló registers, the incomplete January 1990 H-register snapshot, and gradually published B-dossiers (announced through 2027-02-25). Public search absence is inconclusive; never claim the search proves or disproves historical conduct.
- Archive source explanations must be derived from the returned `irattipus`, **not** a person's identity-match score, cover name, or apparent historical role. Preserve prior checkpoints when adding derived report columns; compute them at CSV export.
- The archive updates its online collections over time. HTTP caches/checkpoints are intentionally persistent, so explain `--refresh` when discussing newly published material. No automated live API calls in tests.
- The site's `/api/meta` provides `adatbazis_frissites` (ISO date). Do not infer which records changed from the date alone. The CLI checks it live and stores the last observation under the ignored cache directory.
- Per-person checkpoint `source_updated` is set only when all search responses were live. Old checkpoint entries or cached search responses have unknown freshness. Changing the public dataset must never silently erase prior findings; use `--refresh-stale` or `--refresh` deliberately and keep the dated pre-refresh CSV backup.
- Metadata checks must respect local request pacing/budget and upstream 403/429; tests mock all networking including metadata. `--check-updates` is metadata-only and works without a GEDCOM file.
- Every scan must distinguish fully completed person queries from capped/rejected and interrupted searches. Update the private `*.coverage.csv` report alongside the checkpoint and cumulative matches; `--coverage-only` must remain offline and must not mutate the search checkpoint.
- `completed` means the configured search attempts finished, not that the archive has complete evidence. `limited` means one or more queries were capped, rejected, or invalid; retain warnings in the checkpoint for future offline review. Old checkpoints cannot reconstruct warnings never saved.
- The offline `review_report.py` groups CSV identity leads for verification. It must never fetch records from the archive or infer collaboration from either score or document type. If coverage input is absent, status is `not_reported`; never imply all GEDCOM people were searched.
- Identity contradiction flags refer to the highest-scoring candidate only; do not conflate contradictory identities across different archive records. Do not publish real grouped CSVs or family data.
- Resolve historic place names through `hungarian_places.py`. Verified seed pairs cover Subotica/Szabadka, Odžaci/Hódság, Bačko Petrovo Selo/Péterréve and Čakovci/Csák. `scripts/build_place_index.py` builds a broader **offline** gazetteer from GeoNames language-tagged data. Do not merge ambiguous locations by spelling alone; preserve originals. Accent/case normalization handles `MEZÖKÖVESD` vs `Mezőkövesd`.
- Offline `--rescore-only` must preserve original CSVs and checkpoints, avoid GEDCOM/API requests, and state clearly that filtered-out or undiscovered records cannot be recovered by rescoring.

- On the first `--execute` scan, bootstrap the regional GeoNames index automatically if absent, using all eight configured countries (HU, RO, SK, RS incl. Vojvodina, UA, HR, AT, SI); reuse it on later scans. Only `--no-auto-place-index` skips bootstrap. Preview, coverage, metadata-only, review, and rescoring must not initiate GeoNames downloads.
- GeoNames data is CC BY 4.0. Keep generated ZIPs and CSV in the ignored cache, and do not commit bulky reference datasets. On download failure, stop with an actionable error rather than silently claiming full historical geographic coverage. Place-index changes may alter search filters, so completed searches are not automatically rerun; explain `--refresh` versus offline `--rescore-only`.
- `--include-inferred-married-names` is optional. Derive candidate forms only from an explicit spouse relationship with a recorded marriage event and trustworthy recorded birth/primary name parts; do not fabricate a spouse where the GEDCOM has none. These forms are **unverified search variants**, not legal names, and must be labeled in candidate/review CSVs.
- Never use generated or explicit married-name variants in the `anyja_neve` birth-name filter while inferred-name searching is enabled. Preserve the flag-off checkpoint configuration; keep inferred-name search coverage separate so old checkpoints cannot skip new queries.
- Keep `README.md` limited to the project overview, quickstart, links to detailed guides, and the essential identity/privacy warning. Maintain detailed CLI instructions in `docs/cli.md`, matching algorithms and name/place rules in `docs/matching.md`, and report/archival caveats in `docs/reports.md`. Update those guides when behavior changes; avoid version-history or migration narratives in the README.
- The optional offline `--quality-only` command reports completeness of **saved, score-filtered candidate records**, not archival completeness or real-world accuracy. Keep exported quality CSVs aggregate-only, deduplicate known archive GUIDs per source for record-field completeness, and distinguish candidate-row denominators for scoring/corroboration. Never publish or commit actual names, GEDCOMs, matches or caches. Keep the README short; document quality details in `docs/reports.md` and `docs/cli.md`.
- Synthetic score benchmarks must be deterministic, contain only fictional people and explicitly avoid claims about measured precision/recall or real historical involvement.
- Store new candidate reports and checkpoints in `results/` by default. Ignore the whole `results/` tree plus legacy root-level CSVs/error/checkpoint files (including custom prefixes such as `married_name_matches.*`). Never silently move or delete a user's existing reports; preserve explicit `--output` paths and legacy offline-report accessibility. Document moving an entire checkpoint and its related report files as one set. Keep README concise and put migration details in `docs/cli.md`.
- Grouped identity review now appends `top_evidence_classification`, per-attribute agreement/conflict/missing-GEDCOM details, and per-class counts across candidate rows. Evaluate each archived candidate *separately*: contradictions override agreements within that candidate, and two independent exact identifiers (not merely two partial hits) are needed for a strong corroboration class. Never derive agreement solely from scores or from the presence of identifying fields. Keep legacy top-score ordering, review flags, checkpoints and raw candidate rows unchanged. Document details only in `docs/reports.md` and `docs/matching.md`, not the short README.
- Offline research shortlists live alongside `*.review.csv` under the same `results/` prefix. Prefer **best independent identity evidence** over the largest numeric score, keep the highest-score lead visible separately, and never pool identity fields across archive GUIDs or GEDCOM people. Keep contradictions visible and classify them lower than non-conflicting corroborated candidates. Per-person `gedcom_missing_identifiers` describes family-tree enrichment needs; `missing_gedcom_for_selected_record` lists fields available for direct comparison. Default shortlist excludes name-only and no-candidate relatives without deleting them from other reports; an explicit flag restores name-only leads. All operations must remain offline and not modify saved candidates/checkpoints. Document in `docs/reports.md` and `docs/cli.md`, not the short README.
- Offline score-drift checks must use saved winning GEDCOM match names and corresponding archive identity attributes, and must remain independent of any GEDCOM file, network calls or archive refresh. The `--audit-only` private CSV may list IDs/GUIDs and evidence; print only aggregate counters to the terminal. Audit changes in **score OR evidence text** (classification can change at constant score), report unverifiable/legacy rows, and never silently mutate the existing candidates or checkpoint. `--review-only`, `--shortlist-only`, and `--quality-only` must print drift warnings before using saved evidence; `--rescore-only` regenerates separate candidate, review and shortlist CSVs offline. Test the historically verified Subotica/Szabadka alias only with fictional identities. Do not mistake local scoring freshness for actual archive recency or proof of historical activity.
- Offline chronology/shared-archive-GUID consistency work belongs in `consistency_audit.py`, with an explicit `--consistency-only` mode and two private `results/` files. Parse only unambiguous 4-digit years from saved candidate CSVs. Broad 1944–1990 and B-napló 1956–1962 are *reference ranges*, never event dates; people born before these ranges can still be referenced. A >=65 age at the earliest scope year is only an investigation prompt. Keep approximate/uncertain dates clearly qualified and never assume historical conduct, recruitment or impossibility from age. Group non-empty archive GUIDs by distinct GEDCOM IDs; never equate a shared document with a shared person, or count duplicate searches for one person as multiple identities. Preserve existing score, evidence tiers, search filtering, ranking and checkpoint contents. Integrate non-blocking flags into grouped review/shortlist and generate reports offline without leaking family identities to terminal logs, tests or Git history.
- Collision triage uses `collision_analysis.py`, **never matching names or scores alone**. Group shared nonempty archival GUIDs by distinct GEDCOM IDs, and attach only the evidence class of each candidate row for that *same* GUID/person; do not combine identifying evidence across people or different GUIDs. Three mutually exclusive GUID profiles are `name_only_collision`, `corroborated_lead_present`, and `other_ambiguous_collision`. The source-by-evidence-class `*.collision-summary.csv` must contain only aggregate counts, while `*.collision-triage.csv` includes private IDs and is gitignored. Counts of distinct GUIDs by source/class are not additive; candidate rows are. `--consistency-only` generates these with the existing chronology reports, and review/shortlist/rescore/scan paths maintain them. Research queue P5 fields must describe separate birth-date, mother and birthplace contradictions **on the selected P5 candidate**, while per-person conflict counters may cover other candidates. No automatic exclusion, identity assertions, historical misconduct claims, or changes to saved scores/checkpoints. Test using fictional records only; keep README short.
